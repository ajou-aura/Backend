- T5 CSRF scope now skips only `/api/auth/app/exchange` by path and skips non-cookie clients via an `Authorization: Bearer ` request matcher; cookie-authenticated unsafe `/api/**` requests now require the XSRF cookie/header pair again.
- `SecurityConfigCsrfTest` uses the real `CookieCsrfTokenRepository` flow: fetch `/api/auth/csrf`, reuse `XSRF-TOKEN` + `X-XSRF-TOKEN`, assert cookie-auth POST 403 without CSRF and 200 with CSRF, and assert Bearer POST remains CSRF-exempt.
- Notice scrape buffering no longer does per-row `existsByLink` checks; duplicate detection is deferred to `NoticePersistenceService`, which now batch-loads existing notices with `findByLinkIn(...)` once per chunk and inserts new links with `saveAll(...)`.
- T10 FCM batch sending: `PushNotificationService.sendToUserTopics()` collects `Message` objects for all target users and calls `FirebaseMessaging.getInstance().sendEach(messages)` in batches of 500, replacing the per-user `send()` loop in `KeywordService.onNoticeSaved()`. `BatchResponse` failures are logged at WARN level, not thrown. `sendToTopic()` remains unchanged for topic-based sends.
- `SendResponse` is a final class in Firebase Admin SDK 9.4.2 — its factory methods (`fromMessageId`, `fromException`) are package-private, so tests cannot construct real instances. Mockito 5.x inline mock maker can mock it, but `isSuccessful()` is also final and cannot be stubbed. Test `BatchResponse` failures by throwing `FirebaseMessagingException` from `sendEach()` instead of mocking `SendResponse`.
- `FirebaseMessaging` is not final but `getInstance()` is static. Made `getFirebaseMessaging()` a package-private method returning `FirebaseMessaging.getInstance()` so tests can `spy()` + `doReturn()` a mock, avoiding `MockedStatic` complexity.
